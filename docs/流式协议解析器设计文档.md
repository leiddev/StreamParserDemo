# 流式协议解析器设计文档

## 1. 概述

本方案实现一套可扩展的**流式数据解析框架**，用于 TCP / 串口等字节流场景。  
核心目标：

- 支持**半包、粘包、错包后重新同步**
- 支持多种协议（固定长度、变长、带校验、多字节帧头/帧尾等）
- 每个连接（以 IP 标识）维护独立解析器实例
- 解析出完整帧后通过回调通知上层
- 支持帧接收超时检测与错误回调
- 接口风格简洁：`setFrameCallback` + `feed()`

---

## 2. 设计原则

| 原则 | 说明 |
|------|------|
| 状态机驱动 | 每个协议在派生类中实现自己的状态机 |
| 公共逻辑下沉 | 缓冲管理、超时、回调、粘包循环由基类统一处理 |
| 一连接一实例 | 状态机有状态，必须按连接隔离 |
| 安全优先 | 对长度字段做上下限检查，防止恶意超大帧导致内存耗尽 |
| 零侵入扩展 | 新增协议只需继承并实现 `processByte()` |

---

## 4. 基类 `StreamParser`

### 4.1 公共接口

```
class StreamParser {
public:
    // 完整帧回调
    using FrameCallback = std::function<void(const std::string& tag,
                                             const uint8_t* data,
                                             size_t len)>;

    // 错误回调
    enum class ErrorCode {
        Timeout,            // 帧接收超时
        InvalidHeader,      // 帧头错误
        InvalidTailer,      // 帧尾错误
        ChecksumFail,       // 校验失败
        BufferOverflow,     // 缓冲溢出
        ProtocolError       // 其它协议错误
    };
    using ErrorCallback = std::function<void(const std::string& tag,
                                             ErrorCode code,
                                             const std::string& detail)>;

    StreamParser(const std::string& tag, uint32_t timeout_ms, size_t max_frame_size = 512);
    virtual ~StreamParser() = default;

    void setFrameCallback(FrameCallback cb);
    void setErrorCallback(ErrorCallback cb);

    // 核心接口：喂入一段数据（可任意长度，自动处理粘包/半包）
    void feed(const char* data, size_t size);
    void feed(const uint8_t* data, size_t size);

    // 外部定时器周期性调用（建议 20~50ms）
    void checkTimeout();

    // 连接断开或需要强制清空时调用
    void reset();

    const std::string& tag() const { return m_tag; }

private:
    std::string          m_tag;
    uint32_t             m_timeout_ms;
    FrameCallback        m_frame_cb;
    ErrorCallback        m_error_cb;
    std::chrono::steady_clock::time_point m_last_activity;
    bool                 m_in_frame = false;        // 是否已进入帧中间状态
};
```

### 4.2 受保护接口（供派生类使用）

```
protected:
    // ========== 派生类必须实现 ==========
    // 每收到一个字节调用一次。派生类在此维护自己的状态机。
    // 当判定一帧完整时，调用 completeFrame()；出错时调用 reportError()。
    virtual void processByte(uint8_t byte) = 0;

    // ========== 派生类可调用的辅助函数 ==========
    void completeFrame();                           // 通知上层一帧完成，并重置状态
    void reportError(ErrorCode code, const std::string& detail = "");
    void updateActivity();                          // 有新数据时更新时间戳
    bool isTimeout() const;                         // 当前是否已超时

    // 派生类可直接读写的公共缓冲与状态
    std::vector<uint8_t> m_buf;                     // 当前正在组装的帧
    int                  m_state = 0;               // 协议状态机
    size_t               m_expected_len = 0;        // 变长协议时使用（可选）
    size_t               m_max_frame_size;              // 最大允许帧长

    // 辅助函数
    static std::string toHex(uint8_t byte);         // 将单字节转为十六进制字符串 (如 "A5")
```

### 4.3 核心实现要点

- **`feed()`**  
  遍历每个字节调用 `processByte()`。  
  若 `m_buf.size() >= m_max_frame_size`，立即报 `BufferOverflow` 并重置。

- **`completeFrame()`**  
  调用帧回调 → 清空缓冲 → 状态归零。  
  后续字节自动进入下一帧解析（天然支持粘包）。

- **超时机制**  
  仅当 `m_state != 0`（已进入帧中间）且超过 `timeout_ms` 无新数据时触发。  
  基类只记录时间戳，**需要外部周期性调用 `checkTimeout()`**。

- **错误处理**  
  所有错误通过 `reportError()` 上报，并自动 `reset()`。

## 5. 派生类示例

### 5.1 协议定义

| 字段     | 长度 | 说明                                |
| -------- | ---- | ----------------------------------- |
| 报文头   | 2    | 固定 `0xA5 0x5A`                    |
| 报文长度 | 2    | 大端，值为「报文体 + 报文尾」的长度 |
| 报文体   | N    | 不定长                              |
| 报文尾   | 2    | 固定 `0x55 0xAA`                    |

- 长度字段值 `L ≥ 2`
- 完整帧总长度 = `4 + L`

### 5.2 状态机

| 状态 | 含义                              |
| ---- | --------------------------------- |
| 0    | 等待帧头第一字节 `0xA5`           |
| 1    | 等待帧头第二字节 `0x5A`           |
| 2    | 接收长度高字节                    |
| 3    | 接收长度低字节，计算剩余长度      |
| 4    | 接收报文体 + 报文尾，收齐后校验尾 |

### 5.3 完整实现

```
class A55A55AAParser : public StreamParser {
public:
    /**
     * @param tag          连接标识
     * @param timeout_ms  帧中间超时时间（毫秒）
     * @param max_frame   最大允许帧长度（防止恶意长度）
     */
    A55A55AAParser(const std::string& tag,
                   uint32_t timeout_ms = 300,
                   size_t max_frame = 10 * 1024)
        : StreamParser(tag, timeout_ms, max_frame)
    {}

protected:
    void processByte(uint8_t byte) override {
        switch (m_state) {
        //--------------------------------------------------
        // 状态 0：等待帧头第一字节 0xA5
        //--------------------------------------------------
        case 0:
            m_buf.clear();
            if (byte == 0xA5) {
                m_buf.push_back(byte);
                m_state = 1;
            }
            // 非 0xA5 直接丢弃，保持状态 0（自动重新同步）
            break;

        //--------------------------------------------------
        // 状态 1：等待帧头第二字节 0x5A
        //--------------------------------------------------
        case 1:
            m_buf.push_back(byte);
            if (byte == 0x5A) {
                m_state = 2;          // 进入长度高字节
            } else {
                // 帧头错误，尝试重新同步
                std::string detail = "expect 0x5A after 0xA5, got 0x" + toHex(byte);
                reportError(ErrorCode::InvalidHeader, detail);
                reset();
                // 当前字节可能是新的 0xA5
                if (byte == 0xA5) {
                    m_buf.push_back(byte);
                    m_state = 1;
                }
            }
            break;

        //--------------------------------------------------
        // 状态 2：接收长度高字节（大端）
        //--------------------------------------------------
        case 2:
            m_buf.push_back(byte);
            m_state = 3;
            break;

        //--------------------------------------------------
        // 状态 3：接收长度低字节，并计算剩余需要接收的字节数
        //--------------------------------------------------
        case 3: {
            m_buf.push_back(byte);

            // 大端解析长度：L = 报文体 + 报文尾
            uint16_t L = (static_cast<uint16_t>(m_buf[2]) << 8) |
                          static_cast<uint16_t>(m_buf[3]);

            // 合法性检查
            if (L < 2) {                    // 至少要有 2 字节尾
                reportError(ErrorCode::ProtocolError, "length field < 2");
                reset();
                break;
            }
            if (4 + static_cast<size_t>(L) > m_max_frame_size) {             // 保护
                reportError(ErrorCode::BufferOverflow,
                            "frame length too large: " + std::to_string(L));
                reset();
                break;
            }

            m_expected_len = L;             // 还需要再收 L 字节
            m_state = 4;
            break;
        }

        //--------------------------------------------------
        // 状态 4：接收报文体 + 报文尾
        //--------------------------------------------------
        case 4:
            m_buf.push_back(byte);

            // 已收齐「长度字段声明的」字节数
            if (m_buf.size() == 4 + m_expected_len) {
                // 校验报文尾
                size_t tail_pos = m_buf.size() - 2;
                if (m_buf[tail_pos] == 0x55 && m_buf[tail_pos + 1] == 0xAA) {
                    completeFrame();         // 成功 → 回调 + 自动 reset
                } else {
                    std::string detail = "invalid tail: expected 0x55 0xAA, got 0x" +
                        toHex(m_buf[tail_pos]) + " 0x" + toHex(m_buf[tail_pos + 1]);
                    reportError(ErrorCode::InvalidTailer, detail);
                    reset();
                    // 尝试把当前字节当作新帧头重新同步
                    if (byte == 0xA5) {
                        m_buf.push_back(byte);
                        m_state = 1;
                    }
                }
            }
            break;

        //--------------------------------------------------
        default:
            reset();
            break;
        }
    }
};
```

## 6. 在 TCP 服务中的集成示例

```
#include <unordered_map>
#include <memory>
#include <mutex>

std::unordered_map<std::string, std::unique_ptr<StreamParser>> g_parsers;
std::mutex g_parsers_mtx;

// 帧完成回调
void onFrame(const std::string& tag, const uint8_t* data, size_t len) {
    // 将完整帧放入业务队列或直接处理
    // receiveMsgQ.Add(...);
}

// 错误回调
void onParseError(const std::string& tag,
                  StreamParser::ErrorCode code,
                  const std::string& detail) {
    // 日志 / 统计 / 告警
}

// TCP 收到数据
void onIncomingMsg(const std::string& ip, const char* msg, size_t size) {
    std::lock_guard<std::mutex> lock(g_parsers_mtx);

    auto it = g_parsers.find(ip);
    if (it == g_parsers.end()) {
        auto parser = std::make_unique<A55A55AAParser>(ip, 300, 2048);
        parser->setFrameCallback(onFrame);
        parser->setErrorCallback(onParseError);
        it = g_parsers.emplace(ip, std::move(parser)).first;
    }
    
    it->second->feed(msg, size);
}

// 连接断开
void onDisconnect(const std::string& ip) {
    std::lock_guard<std::mutex> lock(g_parsers_mtx);
    g_parsers.erase(ip);   // unique_ptr 自动析构
}

// 定时器（推荐 20~50ms 周期）
void onTimer() {
    std::lock_guard<std::mutex> lock(g_parsers_mtx);
    for (auto& kv : g_parsers) {
        kv.second->checkTimeout();
    }
}
```

## 7. 关键机制说明

### 7.1 粘包 / 半包处理

- `feed()` 内部对每个字节调用 `processByte()`。
- 一帧完成后 `completeFrame()` 立即将状态清零。
- 剩余字节继续被处理，天然支持粘包。
- 跨多次 `feed()` 的半包由成员变量 `m_state` / `m_buf` 保持。

### 7.2 超时处理

- 仅在「已进入帧中间状态」（`m_state != 0`）时计时。
- 超时时间在构造解析器时指定。
- **必须由外部定时器周期性调用 `checkTimeout()`**，基类本身不启动线程。

### 7.3 错误重新同步策略

- 帧头错误、长度非法、尾校验失败时，调用 `reportError()` + `reset()`。
- 当前字节如果可能是新帧头（例如 `0xA5`），立即尝试重新进入状态机，提高同步效率。

### 7.4 安全防护

- 长度字段下限检查（`L < 2`）。
- 长度字段上限检查（`4 + L > m_max_frame_size`）。
- `feed()` 内逐字节再次检查缓冲大小，双重保险。

## 8. 扩展其它协议

只需新建派生类并实现 `processByte()` 即可，例如：

1. 固定长度协议：状态机更简单，收满固定字节后 `completeFrame()`。
2. 带 CRC 的协议：在收齐后计算校验，失败则 `reportError(ChecksumFail)`。
3. 多字节帧尾 / 转义协议：在状态机中增加对应状态即可。

基类接口保持不变，上层调用代码无需修改。

---

## 9. 注意事项

1. **线程安全**  
   若 TCP 回调与定时器可能并发，请对 `g_parsers` 加锁（示例中已加）。  
   单个解析器实例的 `feed()` / `checkTimeout()` 不建议多线程同时调用。

2. **超时精度**  
   定时器周期建议 20~50ms，过长会降低超时检测灵敏度。

3. **最大帧长**  
   根据实际业务合理设置 `max_frame_size`，既防止攻击，又避免正常大包被误杀。

4. **内存**  
   `m_buf` 使用 `std::vector`，在 `completeFrame()` 后会清空，长期运行内存稳定。

5. **IP 标识**  
   当前以字符串 IP 作为 key。若同一 IP 有多条连接（多端口），建议改用 `ip:port` 或连接句柄作为标识。
